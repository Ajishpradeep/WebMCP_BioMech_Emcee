# YouTube title

Biomech Emcee — Shared 3D Movement Review with WebMCP

# YouTube description

Biomech Emcee is a WebMCP-native movement-evidence review workspace where a human and an AI agent
can inspect and operate the same live biomechanics session.

The working reference workflow is baseball pitching. Synchronized source video and a 3D
reconstruction are presented with phase events, bounded kinematic measurements, confidence,
references, comparison limits, and persistent notes. Instead of placing a chatbot beside this
information, Biomech Emcee exposes the application itself through 13 imperative WebMCP tools: nine
read tools and four write tools.

Through those tools, an agent can:

• understand the active session, frame, phase events, measurements, definitions, and limitations
• navigate the human-visible timeline to supporting evidence
• focus the relevant anatomy and change evidence layers in the live 3D workspace
• explain supported measurements in language appropriate to the user's question
• compare sessions descriptively without implying improvement or causation
• leave persistent, evidence-linked notes for continued human review
• return structured refusals for unsupported quantities such as elbow torque, force, or injury risk

The interaction works in both directions. Agent actions visibly update the same workspace the human
is viewing, while human event-frame corrections immediately change what subsequent agent tool calls
read. This shared state is the core WebMCP contribution: an external agent can reason with and act on
a specialist website without guessing through screenshots, relying on brittle interface automation,
or requiring the website to embed its own fixed assistant.

Biomech Emcee is a review and evidence-navigation system—not an autonomous coach, diagnostic
system, injury predictor, or marker-based motion-capture replacement. Its monocular reconstruction
uses camera-frame coordinates and cannot establish kinetics or metric distances. Comparisons between
the two included sessions are descriptive only because they show different athletes and capture
conditions.

Built for The WebMCP Challenge.
